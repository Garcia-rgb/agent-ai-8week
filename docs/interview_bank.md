# 项目深挖题与故障案例

回答每题时遵循：先给结论，再讲取舍，然后结合仓库代码和实测数据。

## 15 个项目深挖问题

1. 为什么选 LangGraph，而不是纯 LangChain、CrewAI 或自己写循环？
2. 为什么先实现手写 Agent Loop？模型调用工具的完整数据流是什么？
3. 你的 RAG 如何切块？三组参数的结果有什么差异？
4. 为什么采用混合检索？词项与向量分数如何融合？
5. 检索结果正确但回答错误时，你怎么定位？
6. 如何保证引用真的支持回答，而不是只显示一个看似相关的链接？
7. 为什么本地模式使用 Hash Embedding？它有哪些明显限制？
8. 文档重复上传、更新和删除应如何设计？当前实现到哪一步？
9. 用户会话如何隔离？为什么返回 404 有时比 403 更安全？
10. 为什么创建工单需要确认，而订单查询不需要？
11. 确认令牌如何防篡改、防过期和防重放？并发提交会不会有竞态？
12. 模型 API 超时或 429 时系统怎样降级？重试应注意什么？
13. 40 条评测集如何构造？是否存在数据泄漏或覆盖不足？
14. 数据增长到百万 Chunk 后，当前检索实现哪里会成为瓶颈？
15. 如果再给两周，你会按什么顺序改进，为什么？

## 10 个故障排查案例

1. **上传 PDF 后没有 Chunk**：检查 PDF 是否只有扫描图片、解析结果是否为空；需要 OCR 时进入异步任务。
2. **相同文档产生重复记录**：检查字节级 checksum、编码和文档规范化策略，以及数据库唯一约束。
3. **问题相关但 Top-1 错误**：分开观察词项分数和向量分数，检查 Chunk 边界、同义词和权重。
4. **模型回答与引用冲突**：先验证检索，再限制模型只能基于上下文，最后增加忠实度评测。
5. **模型 API 频繁 429**：检查并发和 Token，用指数退避、抖动、限流和缓存处理，不无限重试。
6. **数据库连接耗尽**：检查 Session 是否按请求关闭、连接池配置、慢查询和长事务。
7. **两个用户看到同一会话**：检查查询是否同时使用 session_id 与 user_id，补越权测试。
8. **确认令牌被重复提交**：检查审计记录唯一性和事务；生产环境应给 token hash 增加唯一索引。
9. **Docker API 启动失败**：检查数据库健康状态、连接 URL、pgvector 扩展和应用日志。
10. **评测分数突然下降**：确认数据集版本、模型/Prompt/切块配置和索引是否变化，按 Trace 对比失败样本。
