## 三条纪律

1. 声称「实测」的地方必须能当场复现：命令写在 `README.md` 或 `docs/` 里，跑一次就有输出。

3. 技能栏只留能在面试现场写出最小可用代码的项。写不出来的挪进「了解」。

## 项目：光伏电站技术支持 Agent

时间：2026.xx–2026.xx｜个人项目｜GitHub 地址

- 面向电站运维资料分散、现场排障查询效率低的问题，独立实现支持文档导入、知识问答、设备状态查询与工单创建的 Agent 服务，命令行 `smartpv-agent version|doctor|serve` 可一键自检与启动。（`src/support_agent/cli.py`）
- 检索采用三路信号加权（单字 0.30 + 二元字组 0.35 + 语义向量 0.35）并叠加行业元数据加减分，回答带来源引用；语料 20 份文档切出 212 个检索片段。（`services/rag.py`、`services/industry.py`）
- 语义向量为可切换后端：默认零依赖哈希向量兜底，生产配置走本地 ONNX 模型（bge-small-zh-v1.5，512 维，`onnxruntime` + `tokenizers`，不依赖 torch）；换后端强制重建索引，片段记录向量指纹，维度不一致时拒绝打分而不是给出假分数。（`services/semantic.py`）
- 拒答不依赖分数阈值：实测词汇与语义两个维度上「库内」与「库外」问题**分数区间始终重叠**（哈希向量下 0.182/0.353，语义向量下 0.505/0.604），因此改用「查询词在语料中的缺失比例 + 外文术语完全未知」两个判据并前置在调用模型之前，命中时返回追问而非编造答案。（`services/rag.py::corpus_scope_reason`）
- 一次请求的终态由服务端判定并返回给前端：`completed / degraded / pending_confirmation / needs_clarification / blocked / failed` 六种状态，另有回答来源与是否可重试字段，模型无权声明状态。（`schemas.py`、`services/agent.py`）
- 把工单创建设计为需人工确认的写操作：HMAC 签名、有效期、用户归属、单次使用四道闸，消费记录以 `token_hash` 为主键靠唯一约束原子判定重放，与工单同事务提交（并发下同一令牌不可能建出两条工单）。（`services/security.py`、`main.py`）
- 检索结果做进程内/Redis 双层缓存与按用户固定窗口限流；缓存失败一次即熔断降级，保证缓存不可用时接口只是变慢、不会不可用。（`services/cache.py`）
- 工作流用 LangGraph 编排（条件边分流五种意图），支持检查点与中断恢复，同一 `thread_id` 可续跑；工具调用层独立实现超时、同一工具参数连续失败上限与七类失败分类。（`graph.py`、`services/agent_loop.py`）
- 另实现一个只读 MCP Server（`python -m support_agent.mcp_server`），按协议暴露 1 个 Tool、1 个 Resource、1 个 Prompt，走 stdio JSON-RPC 供外部 Host 跨进程调用；不暴露任何写操作。（`mcp_server.py`）
- 以 pytest 覆盖检索、工具安全、用户隔离、确认流程与缓存降级，共 211 项用例（210 通过 + 1 项需本地模型文件时跳过），覆盖率 88.84%，配套 Ruff、Docker Compose 与 CI。（`tests/`）

## 面试会被追问的点，逐条自己先答一遍

答不上来的就别写进简历。

1. 三路权重 0.30/0.35/0.35 怎么定的 —— 手调，没有网格搜索；为什么加二元字组（「合母」「控母」共享「母」，逐字切分区分不开）。
2. 拒答为什么不用分数阈值 —— 具体数字见上；两维都重叠，只能选工作点并承认误拦（10 条口语化真问题拦了 7 条）。
3. 为什么改了查询分词却不能改 `tokenize` —— 既有向量由它生成，改了查询向量与库里就错位。
4. 缓存里为什么存「命中了哪些片段」而不是片段对象 —— 序列化 ORM 对象脆弱易脱节；片段被删时自然少返回。
5. 缓存键为什么要带向量后端指纹 —— 少带一个就是「改了配置却还读到旧结果」。
6. 确认令牌为什么不能复用审计表判重 —— 审计可轮转清理，判据不能；两者生命周期不同，共用一行等于安全属性静默消失。
7. 为什么验签必须排在判重之前 —— 否则被篡改的令牌会被判成「已使用」，从响应就能反推该令牌存在过。
